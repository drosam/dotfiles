# For Real Contract

- Intent: skeptical verification of completed work, not an unrestricted repair mandate.
- Shape: inline scope → challenge → focused checks → authorized repair/recheck.
- Output: verified behavior and exact check evidence, authorized fixes, blocked checks/residual risks.
- Boundaries: preserve unrelated WIP; verification does not grant installs, production access, edits in review-only mode, commits, or pushes.
- Acceptance: claimed passes correspond to actual commands/results; missing tooling is reported; final diff reviewed after any repair.
- Limits: manual/browser checks may remain unavailable; no fabricated certainty or invented findings.
- Provenance: local history; exact external original unknown. See SOURCES.md.
